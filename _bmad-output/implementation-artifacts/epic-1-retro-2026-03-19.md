## Successes

1. **Velocity far exceeded expectations** — entire epic completed in ~1 day vs 1-2 week estimate. AI pair-programming model proved highly effective.
2. **Nginx spike completed Day 1** — CSS 7 handles content negotiation natively, Nginx just passes headers. Risk retired early.
3. **Story 1.5 breakthrough** — discovered `debug-auth-header.json` config for `Authorization: WebID` header, unlocking real ACL enforcement for the entire PoC.
4. **3-layer code review** (Blind Hunter + Edge Case Hunter + Acceptance Auditor) in Story 1.5 caught 10 issues including a security defect (ACL over-permissiveness).
5. **Handoff notes between stories** worked well starting from Story 1.3 — each story's dev agent benefited from prior discoveries.

## Challenges

1. **Auth mechanism confusion across stories** — Story 1.3 used `X-Ms-User` header (not a real CSS auth mechanism), Story 1.4 inherited it, Story 1.5 discovered the real mechanism (`Authorization: WebID`). Two stories built on a wrong assumption.
2. **Spec vs reality gaps** — Docker image names, Nginx port assumptions for rootless Podman, VOLUME_FLAGS format, ACL role matrix — all had errors discovered during implementation. Expected in fog-of-war, but discoveries must flow forward.
3. **Grant/revoke didn't persist in CSS dev mode** until Story 1.5 fixed the auth config. Stories 1.3/1.4 treated HTTP 401 as success (intentional PoC design, but masked a real problem).

## Key Insights

1. **Fog-of-war requires systematic learning propagation** — handoff notes between stories are critical. Without them, wrong assumptions contaminate downstream work. Nicolas identified this as the core lesson.
2. **Story-level soft-retros needed** — a structured reflection at story completion to capture struggles, solutions, and handoff lessons while they're fresh.
3. **Memory hygiene is part of the retro** — not just "what did we learn" but "what do we think we know that's wrong now?" Stale assumptions in memory can poison future work.
4. **Code review is a critical safety net** — the 3-layer review in Story 1.5 caught a security defect that would have carried into Epic 2.
5. **Embedding model choice is reversible** — pod layer is source of truth (DA-1), derived layers (graph, vector) are rebuildable. Don't over-invest in upfront model selection at PoC scale.

## Durable Knowledge (propagate to Epic 2+)

### Authentication
- `Authorization: WebID <webid>` is the ONLY valid auth mechanism for CSS 7
- `X-Ms-User` header does NOT work — CSS ignores it
- CSS must be configured with `debug-auth-header.json` (UnsecureWebIdExtractor)
- WebID format: `http://localhost:3000/{agent-name}/profile/card#me`

### CSS Behavior
- HTTP 205 (Reset Content) for successful ACL PUT updates — accept `[200, 201, 205]`
- Pod operations go through CSS directly on port 3000, NOT Nginx on 8080
- Nginx is for content negotiation only (Accept header pass-through)
- Provisioner needs `<#provisioner>` Control entry in all pod ACL files

### ACL Matrix (corrected in Story 1.5 review)
- Individual pods (ayoub, claire-student-*, fatima-child-*): owner + tutor/parent + provisioner only
- marc and isabelle have NO access to individual pods — school-community only
- troll has no access anywhere
- school-community: marc (R/W/C), claire/fatima/ayoub/isabelle (R)

### Infrastructure
- Named volumes (not bind mounts) for SELinux compatibility
- Rootless Podman: Nginx on 8080/8443 (can't bind < 1024)
- `VOLUME_FLAGS=,Z` (comma-separated) for bind mounts on Fedora
- `distrobox-host-exec` for accessing podman containers from within distrobox
- `podman compose down <svc> && podman compose up -d <svc>` to reload config (restart doesn't work)

### Troll Patterns (reuse in Stories 2.6, 2.7, 2.8, 3.8, 5.3)
- `TrollTestResult` dataclass + `log_test_result()` — import from `agents/troll-adversary/attacks/__init__.py`
- `access_path="direct"` for HTTP tests, `"through_skill"` for SPARQL/Qdrant-mediated
- 401 and 403 both valid enforcement responses — treat both as `"pass"`
- `authorized-denied` = `"fail"` (blocking), not `"partial"`
- 5xx/3xx → `"partial"` (infrastructure issue)
- Always include preflight check before running troll suite
