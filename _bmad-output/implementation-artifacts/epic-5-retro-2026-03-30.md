## What Went Well

### Anagnorisis Backlog Shipped in Full
The three Anagnorisis stories (5.4–5.6) were backlog items with uncertain scope at Epic 3 retro. All three shipped, each implementing a distinct architectural principle. The epic over-delivered on its own scope.

### Three-Layer Atomic Discipline
Every story treats CSS, Oxigraph, and Qdrant as independent failure domains. The deletion cascade, access receipts, and token expiry all apply the same discipline: each layer is verified independently, partial failures are logged and reported honestly, no silent swallowing.

### Tombstone Pattern Unified Across Stories
`poc:revokedAt` empty = active, populated = revoked. Applied consistently across ACL revocation (5.2), consent revocation (5.5), and ephemeral token expiry (5.6). One mental model, three modules — no reinvention.

### EphemeralConsentGrant Extends ConsentGrant
Story 5.6 subclassed the 5.5 consent model cleanly. Architectural coherence across consecutive stories — the 5.5 design was built to be extended and was.

### Non-Blocking Side Effects Consistent
Receipts, JSONL writes, logging failures never abort primary operations. Applied uniformly across 5.4, 5.5, 5.6 — a system-design choice, not an improvised story-by-story decision.

### sys.modules Registration Pattern Documented
After `importlib.exec_module()`, `sys.modules["name"] = _mod` is required for `@patch` decorators to target the correct module object. This failure class is now documented in memory and won't recur.

### SKILL.md Format Corrected Early (5.1)
Context7-verified: only `name` and `description` fields supported by OpenClaw. Unsupported `inputs`/`outputs` schema removed. Fog-of-war invalidation in the first story prevented drift across all subsequent stories.

### Project Lead Observation
Nicolas: "Each story builds up well, and the reviews validate progress. The consent machinery is live code now, not prose — that matters."

## Challenges

### Walking Blind — Test Suite Confidence Gap
Nicolas named the same concern as Epic 3: trusting that tests represent real behaviour without the dashboard to observe the system live. In Epic 5 this was concrete: 12 patches in 5.2 fixed real bugs (silent exception swallowing, parameter shadowing, wrong accumulation logic) — none of which broke existing tests. Tests were real; coverage had a systematic blind spot on atomicity edge cases and failure-branch paths.

**Root cause:** Happy-path mocks don't exercise failure branches. Multi-layer operations need explicit "step N succeeds, step N+1 fails" test cases.

**Resolution:** Deferred to Epic 6.1 (Rex troll sweep will surface gaps). Dashboard in 6.2 will make silent failures visible. This is the intended architecture of the PoC.

### Stale Assumption Pollution (5.5 or 5.6)
Dev was still building on `agent.yaml` — a pattern superseded by the SOUL.md/AGENTS.md/IDENTITY.md workspace. The leftover came from story file context. The cleanup between stories was not thorough enough.

**Root cause:** Story files carried forward deprecated scaffolding. Fog-of-war invalidation caught it but too late — after dev had already started on the wrong foundation.

**Resolution:** Add an explicit "Invalidated Assumptions" section to the story creation template, pre-populated by SM from current memory entries at story creation time. Replaces a token-expensive Haiku sweep.

### Story 5.2 Patch Density (12 patches)
Highest review patch count of the epic. Categories: silent exception swallowing, parameter shadowing, event naming inconsistency, HTTP response guard, false positive anchoring, atomicity guards. None caused test failures.

**Root cause:** 5.2 is the most complex story — touches all 3 layers, fixes a privacy vulnerability, introduces UUID index, is stateful across stories. Patch count is proportionate to scope.

**Mitigation:** All caught in review, zero regressions. The review process worked. Pattern to watch: error swallowing and atomicity edge cases are the two recurring failure modes.

### Atomicity Asymmetry Decision (5.5)
Tombstone write takes priority over ACL consistency: if ACL revocation fails after tombstone is written, log the inconsistency, do NOT rollback. GDPR Article 7(3) audit trail trumps operational consistency. This is a hard architectural call — documented explicitly in 5.5.

## Recurring Code Review Patterns

Two patterns appeared across multiple stories — added to standing review checklist:

1. **Error swallowing:** Catching exceptions without logging or re-raising. Caught in 5.2 (P-5), 5.4 (P-4). Fix: explicit `WARN` log or `RuntimeError`.
2. **Atomicity edge cases:** Multi-layer operations need explicit guards for "step N succeeds, step N+1 fails." Caught in 5.2 (P-1, deregister_hash guard), 5.5 (rollback strategy).

## Key Architectural Findings

### Pipeline Gap: camp-dietary-aggregate.ttl Not Seeded
After `podman compose down -v` → `up -d` → `provision_pods.py` → `run_pipeline.py`:
- `school-community` pod exists ✅ (provision_pods reads pod-config.yaml)
- access-log ACLs configured ✅ (provision_access_log_acl called per pod)
- `camp-dietary-aggregate.ttl` NOT loaded ❌ — not in pipeline stages, not in provision_pods

The community pod is empty after a full reset. The ephemeral consent / food service demo scenario fails silently.

**Resolution:** Story 6.0 — add Stage 0 to `run_pipeline.py`: provision pods + seed community pod data, emitting JSONL like all other stages. Full demo run becomes a single command: `compose down -v` → `compose up -d` → `run_pipeline.py`. No manual steps.

### Demo Run Strategy Confirmed
- **Full reset:** `podman compose down -v` + `podman compose up -d` (volumes gone, clean slate)
- **Not `--wipe`:** Too slow, partial — doesn't address community pod gap
- **Single pipeline command:** `run_pipeline.py` with Stage 0 provision (Story 6.0)
- **Pilot scope:** Backup, data persistence, and incremental provisioning are infrastructure concerns — out of PoC scope
