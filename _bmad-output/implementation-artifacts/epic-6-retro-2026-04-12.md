## What Went Well

### ACL Dashboard Is a Keeper
The 6.2 pivot produced the most effective demo artifact of the entire POC. One page: 6 pod cards, live ACL state, probe/grant/revoke cycle. A funder clicks Grant, probes, gets 200. Clicks Revoke, probes again, gets 401. The whole argument in one gesture.

**Nicolas:** "That page is a keeper. Probing from different actors and unknowns is clear. Revoking is clear. Granting is clear."

### Fog-of-War Pivot Worked
The TUI (mission_control.py) was built against JSONL mock data with 16 fictional pods. It visualized data flows — which isn't the demo moment. The pivot to a FastAPI + HTML dashboard that proves real boundaries was the correct course correction. The team built the wrong thing, recognized it, and pivoted. That's the process working.

**Nicolas:** "We tried too much with TUI and previous dashboard to visualize everything at the same time, all scenarios together. This was a mistake we ended understanding with this simple ACL dashboard. This is fog-of-war — we move on based on ideas and assumptions, we test, maybe fail and pivot."

### Troll Machinery Solid (6.1)
Five attack categories, orchestrator with JSONL events, blocking/non-blocking distinction, human-readable markdown report, per-category JSON files. The troll plumbing is stable and won't need rework.

### acl-manage Skill Wiring Clean (6.3)
Grant and revoke routed through OpenClaw's skill layer with subprocess calls. The demo now shows agent-mediated consent, not direct database calls. Architecturally significant for Epic 4 where agents become the primary interaction model.

### Winston's Scope Principle
"The dashboard that works is the one with the smallest scope." ACL cards represent one abstraction level: pod → access state → probe → grant/revoke. The TUI tried four abstraction levels simultaneously. One layer at a time.

**Decision:** Intentional deferral. The troll report (6.1 markdown) is the authoritative output. The UI wrapping was dropped because a better interaction model emerged: troll lives on Discord (see Architectural Decisions below).

## Architectural Decisions (Epic 6 Retro)

### Decision 1: Discord Over Telegram for Multi-Agent Interaction
**Decided:** 2026-04-12
**Rationale:** One server, multiple channels, unified observer experience, role system mirrors ACL personas, bot token auth (no QR pairing friction). Telegram fragments agents across separate group chats.
**Impact:** Epic 4 agents reachable via Discord channels. Troll posts to #security_logs. Agents can observe each other's channel activity.

### Decision 2: Troll Lives on Discord, Not Dashboard UI
**Decided:** 2026-04-12
**Rationale:** Interactive explanation (funder DMs the troll) > static counters. Heartbeat-triggered periodic runs + short reports on #security_logs. The markdown report (6.1) remains the authoritative document.
**Impact:** Troll tab in dashboard is deprioritized. Troll's HEARTBEAT.md defines periodic probe runs.

### Decision 3: Seed-on-Boot, Not Bind Mount for Agent Workspaces
**Decided:** 2026-04-12
**Rationale:** Agents must evolve through interaction (MEMORY.md, SOUL.md refinement). Read-only bind mount blocks this. Dockerfile COPY to `/app/agents-seed/`, entrypoint seeds writable workspace on first boot. `compose down -v` = factory reset.
**Impact:** Workspace paths in `openclaw.json` change from `/app/agents/` to `/home/node/.openclaw/workspaces/`. Named volumes per scenario enable isolation.

### Decision 4: Nicolas as New User Proves Onboarding Flow
**Decided:** 2026-04-12
**Rationale:** Adding one real user (own pod, own agent-assistant) validates provisioning without premature generalization. Tests: add content to pod, grant/revoke access, observe propagation, interact with personal agent.
**Impact:** Story 4.1 or 4.2 includes a "new user onboarding" task. pod-config.yaml gets a nicolas entry.

### Decision 5: ACL Dashboard Survives Into Epic 4
**Decided:** 2026-04-12
**Rationale:** First POC artifact that persists across epics. ACL cards are a keeper — clear, simple, funder-facing. Epic 4 runs with dashboard live alongside Discord agent interaction.
